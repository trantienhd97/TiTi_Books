    TASK ASSIGNMENT AUTO-TRIGGER - PHÂN TÍCH CHI TIẾT¶

    📋 TÓM TẮT¶

    Hệ thống hỗ trợ tự động tạo Task Assignment khi User trả lời các câu hỏi kiểm tra dựa trên các quy tắc (Logic Conditionals) đã được cấu hình từ Backend.

    🔄 FLOW TẠO TASK TỪ MOBILE (DYNAMIC MIRRORING)¶

    Để đảm bảo UX mượt mà (0ms feedback) mà vẫn giữ đúng logic của Backend, chúng ta sử dụng cơ chế Dynamic Mirroring: Mobile sẽ tự động tính toán và hiển thị danh sách Task ngay lập tức ở chế độ Read-only.

    Quy trình xử lý Logic:¶

    1. Trigger: Ngay khi User thay đổi đáp án (Check/Uncheck option, nhập số, nhập chữ).
    2. Re-evaluation (0ms):
      • MB lấy danh sách đáp án hiện tại của câu hỏi.
      • MB duyệt qua tập hợp inspectionQuestionConditionals của câu hỏi đó.
      • So sánh đáp án với toán tử (operatorId) và giá trị trigger.
    3. Task Management (Cập nhật danh sách):
      • Add: Nếu đáp án mới thỏa mãn một rule tạo task (triggerId = 2) → MB sinh ra 1 Task object mới.
      • Remove: Nếu User bỏ chọn (Uncheck) một đáp án mà trước đó đã sinh task → MB xóa ngay task đó khỏi danh sách hiển thị.
      • Maintain: Giữ nguyên các task của các đáp án vẫn đang thỏa mãn.
    4. UI Representation:
      • Tên Task: Lấy trực tiếp từ thuộc tính taskNameTemplate trong config tải về máy.
      • Chặn tương tác (ReadOnly): MB đánh dấu isAutoGenerated = true. Trên UI, onTap của ListTile sẽ bị chặn (null) để User không thể chỉnh sửa task tự động này.
      • Visual: Hiển thị mờ hơn hoặc kèm label "Task tự động" để phân biệt với task user tự tạo tay.

    🎯 ĐẶC ĐIỂM CHO LOẠI CHỌN NHIỀU (MULTIPLE CHOICE)¶

    Với câu hỏi chọn nhiều đáp án, logic xử lý phức tạp hơn do một câu hỏi có thể có nhiều task cùng lúc:

    • Độc lập: Mỗi phương án trả lời (Option) có thể gắn với một Rule khác nhau.
    • Tập hợp: Danh sách taskAssignments hiển thị dưới câu hỏi sẽ là tổng hợp của các Rules thỏa mãn tại thời điểm đó.
    • Ví dụ:
      • Chọn "Lỗi điện" → Hiện Task "Kiểm tra hệ thống điện".
      • Chọn thêm "Lỗi nước" → Hiện thêm Task "Kiểm tra đường ống nước".
      • Bỏ chọn "Lỗi điện" → Chỉ còn lại Task "Kiểm tra đường ống nước".

    💻 IMPLEMENTATION GUIDE¶

    1. Model Extension¶

    Thêm cờ isAutoGenerated để quản lý việc chặn click.

    class TaskAssignment extends JsonModel {
  // ... existing fields
  JsonBoolean isAutoGenerated; // Mac định false, set true cho task sinh từ logic
}

    2. Logic cập nhật danh sách Task (MB Engine)¶

    List<TaskAssignment> evaluateAndSyncTasks(
  InspectionQuestion question, 
  List<InspectionQuestionAnswer> currentAnswers,
  List<ConditionalRule> rules
) {
  // 1. Tìm các rules thỏa mãn đáp án hiện tại
  final triggeredActions = rules
    .where((r) => r.questionId == question.id.value && _checkMatch(r, currentAnswers))
    .expand((r) => r.actions)
    .where((a) => a.actionType == CREATE_TASK)
    .toList();

  // 2. Tạo danh sách Task mới (Read-only)
  return triggeredActions.map((action) {
    return TaskAssignment()
      ..name.value = action.taskNameTemplate // Rule lấy tên từ config
      ..isAutoGenerated.value = true;        // Chặn click
  }).toList();
}

    3. UI Widget (Block Interaction)¶

    ListTile(
  title: Text(task.name.value),
  // ⭐ CHẶN BẤM TẠI ĐÂY
  onTap: task.isAutoGenerated.value ? null : () => navigateToTaskDetail(task),
  // Visual feedback
  enabled: !task.isAutoGenerated.value,
  subtitle: task.isAutoGenerated.value ? Text("Tự động tạo") : null,
)

    📝 SUMMARY¶

    ✅ Tốc độ: 0ms, task hiện/ẩn ngay khi user thao tác.

    ✅ Read-only: User không thể can thiệp vào task do logic sinh ra.

    ✅ Đồng bộ: MB tự quản lý việc Add/Remove task khi User "nhảy" đáp án liên tục.

    ✅ Call API: MB vẫn call API lưu answer để Backend đồng bộ dữ liệu thật ở phía Server.
